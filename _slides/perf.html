1.1 Workload Analysis

Starting Point: Application Layer

Requests

Workload applied to the application. This is the gauge that tells if you are trying to handle an unresonable ammount of work all at the same time. Even more, doing a workload characterization can uncover some unbalances in how that workload is distributed.

Latency

The time it took the application to execute the work. Arguably the most important metric for an applications performance and it needs to be very well defined. As an example, for a database engine it can refer to the query latency or connection latency. Another mandatory mention here is throughput, as the sister opposite metric.

Completion

Determines if the system had any errors during the workload. If there is a fail-fast path and the system experienced some errors that converged in that said path the results of the analysis will be very good or very bad, depending on the retry mechanism or other factors.

1.2 Resource Analysis

Starting Point: Hardware Layer

Utilization

Very common metric that that indicates a potential issue with a resource that is about to reach it's limit.

Saturation

Complementary metric or indicator of utilization that tells if the resource is under heavy load, more than it can handle.

Capacity (Planning)

Provisioning and scaling policies are alwasy hard to get right. Resource analysis should help with decisions regarding this.
